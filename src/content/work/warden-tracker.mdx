## Overview

Warden Tracker is a geo-fencing system — background location feeds spatial queries which trigger low-latency proximity alerts via native push. Built at Sadguru Soft; the technical interest is in keeping the location loop honest while battery cost stays defensible.

## Problem &amp; context

The phrase "high-precision geo-fencing" gets thrown around easily and is much harder to deliver. The classic trap is letting GPS updates dominate the battery budget; the second-classic trap is over-quieting location and missing the fence-cross. Warden's success criterion was hit-rate on real proximity events, not pretty maps.

## My approach &amp; key decisions

- **Background location tuned per platform** — Android foreground service with a sensible duty cycle, iOS background modes with significant-location-change fallbacks.
- **Spatial queries on-device** for the fence-cross detection, kept on the device so the alert can fire instantly.
- **Native push for proximity alerts**, with a delivery path that doesn't depend on FCM being awake.

## Architecture &amp; stack

- **Client:** Flutter (Dart).
- **Location:** Native background services per platform.
- **Spatial:** On-device fence-cross detection.
- **Notifications:** Native push channels.
- **Distribution:** Internal / B2B project. Never on public app stores.

## Challenges

- **Battery vs. event-hit-rate.** Tuning the duty cycle so neither the device dies mid-day nor the fence-cross goes silent.
- **Spatial query speed on the device.** The check has to be fast enough not to add latency between cross and alert.
- **Same-name confusion in research.** Several unrelated "Warden" / "WardenGPS" apps exist on both stores — none are this build.

## Results &amp; impact

- Internal / B2B client project. Never on public app stores.
- Cross-referenced against APKPure and aggregator listings during research — no public mirror or alternate distribution surfaced, consistent with the internal-tool framing.
